# 开发全程与当前任务

## 协作节奏

每轮完成一个能运行、能验收的功能。AI 给出模块职责、接口和实现指导；用户写核心实现；AI 读取文件、解释问题、指导修正，并完成相应验证。
遇到不熟悉的类、类型注解、HTTP、数据库或界面机制，就在实际功能中解释。项目骨架、文档和配置由 AI 维护。

## 阶段 0：设计与环境
- 产物：虚拟环境、项目包结构、架构、开发与验收文档。
- 当前：虚拟环境已验证；设计与最小包骨架已建立。
- 已确认：用户提供的教务入口为 http://ijw.hzcu.edu.cn/。
- 待确认：实际选课子页面、选课开放时间、学校系统的登录和查询方式。
- 本轮入口读取没有成功取得正文，原因尚未定位；不能由此认定系统仅限校园网。

## 阶段 1：课程查询的完整模拟链路
- 功能：命令行输入课程关键词，经应用服务调用模拟适配器，显示匹配的教学班、教师、容量和余量。
- 文件：domain/models.py、adapters/school.py、adapters/mock_school.py、application/catalog.py、interfaces/cli.py，以及必要的 __init__.py。
- 学习：包导入、数据模型、模块边界、接入约定、入口参数和错误处理。
- 验收：同名不同班可区分；满员与有余位正确显示；无匹配与未知状态有清晰结果；不访问真实网络。
- 测试：应用服务和 CLI 的可观察输出，覆盖模拟接入返回空列表、异常数据及错误的情况。

## 阶段 2：可恢复的模拟监控任务
- 功能：创建/取消任务、周期检查、记录状态、模拟通知、重启后恢复。
- 文件：tasks.py、monitoring.py、storage/、worker.py、通知适配器。
- 学习：数据库、状态机、调度、异常恢复、可取消等待和运行配置。
- 验收：模拟满员变有位只产生一次相应通知；取消后不再提交；断网退避；任务重启不丢；通知失败不重选。
- 先通过控制台验收 worker，不把无限循环塞进界面。

## 阶段 3：真实教务只读接入
- 功能：用户自行登录，查询真实课程和已选列表，识别会话失效。
- 先调查：课程唯一 ID、学期、查询分页、容量字段、是否可选、接口限频与认证方式。
- 数据材料：只保存脱敏接口形状和必要字段，不保存可复用凭据。
- 验收：与真实页面对照教学班和余量；错误页/验证码页不被当成课程结果；用户真实重新登录后恢复查询。
- 本阶段不执行真实选课、退课。
- 提前评估云端网络可达性和登录流程，为 Web 决策提供证据。

## 阶段 4：桌面操作入口
- 功能：登录状态、课程搜索、监控列表、开始/停止、模式选择、日志和通知。
- 学习：界面事件、后台线程、信号更新、界面和业务分离。
- 验收：查询时界面仍响应；停止可用；模拟/真实来源清晰；最小化后任务可继续。
- “关闭窗口继续”需显式托盘逻辑；退出程序应停止执行，不能混为一谈。

## 阶段 5：选课流程与结果核验
- 先在模拟适配器验证：抢位失败、已选、冲突、会话过期、提交超时、崩溃后的不确定结果。
- 再在用户明确指定课程和模式后做真实提交测试。
- 验收：真实已选列表确认成功；失败原因清晰；不盲目重发；成功停止该任务；通知独立重试。
- 没有真实空位/明确授权时，保持真实选课未验证，不能用模拟测试替代。

## 阶段 6：桌面试用与打包
- 功能：配置、运行数据目录、日志脱敏、打包、使用说明。
- 验收：其他机器无需开发环境即可启动；真实登录、查询、停止和数据保存分别验证。
- 若增加安装器，安装/升级/卸载与数据保留单独验收。生成 EXE 不等于这些检查通过。
- 记录实际依赖版本与构建方式，依赖安装后更新配置和可复现记录。

## 阶段 7：网页版的完整模拟链路
- 功能：网站身份、自己的课程任务页面、任务 API、持久化数据库、独立 worker、通知渠道。
- 页面与 API 首期同源提供；先使用模拟学校，不直接迁移真实用户凭据。
- 学习：HTML/CSS/JavaScript、HTTP/JSON、API、服务器身份校验、数据库和后台进程之间的关系。
- 验收：用户 A 不能读取/取消用户 B 的任务；关闭网页仍执行；API/worker 重启后状态恢复；只有一次提交动作；通知可核验。

## 阶段 8：真实服务器部署与公开试用
- 前置：从服务器实测学校可达性；确认真实认证、会话续期和安全存放方案。
- 功能：正式运行环境、HTTPS、进程管理、受保护的配置、数据库迁移与备份恢复、整体限频。
- 先小规模试用，再据学校接口表现调整用户数和监控频率；桌面与服务器请求的限制分别评估。
- 验收：关闭用户浏览器/电脑后仍监控，真实结果与通知对照；服务器重启后任务恢复；会话失效明确提示；备份可恢复。
- 前置不满足时记录实际限制，不能发布“云端可持续选课”的承诺。

## 第一轮具体任务：课程查询，而非孤立语法练习

本轮目标：从终端查询模拟课程列表，建立后续 GUI/Web 共用的查询入口。

调用顺序：CLI → CourseCatalogService → SchoolAdapter → Course/CourseStatus → CLI 显示。

拟定接口：
- Course：school_id、term_id、section_id、name、teacher。
- CourseStatus：course、capacity、selected、available、checked_at。
- SchoolAdapter.list_courses(keyword: str) -> list[CourseStatus]。
- CourseCatalogService.search(keyword: str) -> list[CourseStatus]。

模拟适配器准备至少三个教学班，包含同名不同教师、满员与有位的情况。搜索规则先使用课程名子串匹配，空关键词返回全部。异常人数或缺字段返回明确的接入错误，不能假造余量。

课程状态的实时快照与课程身份分开，后续再次查询可更新人数而保持同一个教学班 ID。

写代码前，AI 先解释这个调用链以及每个文件的作用，再指导用户实现这一整段。完成后由 AI 运行模拟验收；这不是已经实现的接口。

当前只有 src/kelai/__init__.py。拟定运行入口在实现后为：

```powershell
python -m kelai.interfaces.cli search 羽毛球
```

预期能区分不同教学班并显示教师、容量、已选、余位，输出中明确标注“模拟数据”。当前命令尚不可运行。
